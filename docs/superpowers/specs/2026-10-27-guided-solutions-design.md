# 编程题分步学习与双运行模式

状态：用户已确认并授权实现。2026-10-27。

## 目标与已确认选择

面向当前鼠标版及荣耀平板阅读场景，把扫描后只展示标签、点击直接进入代码的流程，改为可以理解方法依据、逐步实现和图解，再阅读对应代码的流程。

用户已确认：默认 LeetCode 核心解法，附完整本地运行入口与测试数据；按钮切换 ACM 标准输入输出版。分析、图解和两个代码版本一次生成，确保来自同一份解法。

## 方案比较

1. 一次生成完整学习内容：首轮输出较长，但分析步骤和代码可用稳定编号对应，后续切换无额外模型等待。用户选择此方案。
2. 按访问页面逐步生成：首屏较快，但阅读过程中反复等待，不同调用需要额外保证一致性。未采用。

沿用 Node 服务、原生浏览器页面、现有模型选择和采集链路。结构化内容由服务端校验，前端从数据绘制图解；图解无需额外图片生成 API。

## 阅读与操作流程

目录 → 分类/思路概览 → 思路分析 → 具体实现 → 结构化图解 → 代码。

- 分类/思路概览保留题意、分类标签、思路标签、题单对照。
- 思路分析说明题目类型、题目条件为什么适合该方法、关键不变量或正确性依据，以及时间/空间复杂度。内容是教学说明。
- 具体实现按 S1、S2、S3 等步骤展开，每步包含目的、输入/状态、具体操作、边界情况。
- 图解展示与题目相关的流程、数组/链表/树/图结构或状态变化，节点与步骤编号关联。示例来自题面；没有题面示例时明确标为“演示示例”。支持放大查看，不把图挤成无法阅读的缩略图。
- 代码页默认显示 LeetCode 本地可运行方案。代码和运行说明一起呈现。
- 顶栏有各阶段按钮及前进/后退按钮，触摸和鼠标均可使用。鼠标左键点击非交互区域沿上述顺序前进，右键逐级后退。代码页空白处单击截新图、长按连拍的现有行为保留；代码内选择、复制、滚动以及切换按钮不触发截图。
- 代码页提供 LeetCode / ACM 两个模式按钮，不再次调用模型；切换不离开当前题。
- 一批多题时以题号选择当前题，阶段、图和两个版本始终属于该题。

## 代码展示与运行约定

- VS Code 风格：深色代码底色、语法高亮、等宽字体、行号、缩进引导、步骤分块标题。属于只读代码阅读器，不引入完整编辑器。
- 核心代码块使用与思路页相同的 S1…Sn 编号与标题；初始化、入口、输入输出等辅助块单独标识。点击步骤可定位代码块。
- 展示完整且连续的源代码，不因视觉分块插入不能运行的内容。支持复制完整代码；步骤标题不是源代码文本。
- 注释解释状态含义、操作依据和边界处理。保留已有代码的“改：/补：”注释语义，合理沿用原变量名及函数划分。
- LeetCode 默认包含 Solution/核心函数、所需 import/头文件、必要结构定义、测试数据、调用入口和预期输出。Python 使用 `if __name__ == "__main__":`；其他语言使用对应入口。标清本地辅助代码与平台提交所需部分，提供复制核心提交代码的入口。
- ACM 包含标准输入读取、完整入口、算法及标准输出。优先遵循题面输入输出；题面没有标准输入格式时明确给出“本地约定”，不冒充原题规则。提供可复制样例输入和预期输出。
- 树/链表等结构补齐本地构造与结果展示，不只留下平台提供的隐含类型。若题面缺少决定答案的条件，则说明缺失，不编造可提交解。
- 编程语言沿用项目已有规则：题面/任务背景优先，其次截图中的语言，均无法判断时 Python。两个模式使用同一语言与核心算法。
- “可运行方案”指展示代码、样例、命令和预期结果；本次不在服务器执行模型生成的任意代码，也不声称所有生成答案经过真实编译验证。

## 数据、生成与兼容

新增带版本号的结构化学习数据（例如 `lesson.version = 1`），与原有 job 一起保存。

每道编程题包含：题号、题意、语言、分类/思路、方法依据、正确性说明、复杂度、实现步骤、结构图节点/连线或状态帧，以及 LeetCode/ACM 两份源码、步骤行区间、核心提交区间、运行说明和样例。图节点与代码区间引用有效的步骤 ID。

服务端验证必需字段、长度上限、步骤引用、图连接和代码行范围。模型输出只作为数据，不作为 HTML/JavaScript 执行。结构图由受控组件绘制，代码使用安全的文本与高亮渲染。

生成仍使用现有 provider.ask 接口，以提示词约定结构化输出，不要求所有供应商支持特定 JSON API。编程题结构无效时明确记录生成失败并允许用户重试，不能把缺失的 ACM/图解伪装为完整成功。普通题沿用现有答案/解析流程；一个批次混合题型时保留普通题答案并支持编程题选择。

题单对照继续在答案生成后进行，从结构化题意与核心代码构造输入，不将本地入口/双份代码重复发送。对照失败不影响已生成的学习内容。

列表摘要不携带大块源码/图解，详情接口按需加载。刷新和重连能够恢复已生成内容，无需重新调用模型。

旧记录继续可阅读并显示现有分析/代码；没有新结构的记录不伪造分析、图解或双模式，明确提示重新截图可生成新版内容。不批量改写或自动重新分析历史记录。

## 平板布局

以实际 CSS 视口响应布局，不把 2560×1600 物理像素当作网页尺寸。保留现有横屏/反向/跟随设备设置。

分析页采用可滚动短段落；代码保持可调字号/每屏行数，长行支持换行或横向滚动，不裁掉右侧代码。图解在独立容器内缩放，不影响页面导航。顶栏在窄视口换行，核心按钮保持可触摸。

## 验收

1. 新编程题沿概览→分析→实现→图解→代码前进，右键和按钮可逐级后退。
2. 每个实现步骤在图解和代码中可找到对应编号；两个模式的核心算法一致。
3. 默认 LeetCode 包含完整本地入口、数据与必要结构定义，ACM 包含输入输出和样例。
4. 触摸/鼠标点击切换、复制、图解操作不会误触发截图。
5. 单题、多题、普通题、混合题、旧记录、损坏输出和重新连接有明确可用行为。
6. 自动测试覆盖解析校验、存储/接口、导航及输入冲突。演示数据使用代表性算法完整展示流程，不消耗模型额度。
7. 浏览器检查横竖屏和典型平板 CSS 视口，项目测试通过；真机最终观感由用户在平板确认。

## 实现者可自行决定

结构化字段精确命名、渲染模块拆分、语法高亮库、图形布局算法及视觉细节由实现阶段决定；依赖尽量本地提供。实现中不新增外部服务，不更换现有模型/采集器，不批量重写历史数据。服务重启前确认没有正在生成的任务。
